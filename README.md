# 新云传媒户外提案台

面向 2027 年上海户外媒体投放的交互式 HTML 原型。现场可换行业、预算、媒体和档期，查看预算差异，打开逐项依据，或移除一个点位后重新配案。

## 运行

双击 `提案台.html`，用 Edge 或 Chrome 打开。单文件包含样例目录、规则、图表和 Excel 导出库，可离线运行。

从源代码生成页面需要 Node.js 20 或更高版本。

```powershell
node scripts/build.cjs
node --test tests/planner.test.cjs
```

需要在同一网络内提供评审预览时，可把生成的 HTML 交给静态托管，或从仓库目录运行 `python -m http.server 8765 --bind 127.0.0.1` 并以 `http://127.0.0.1:8765/提案台.html` 在本机访问。

## 演示顺序

1. 从连锁咖啡品牌 A 出发。默认 200 万、公交和地铁、2027-06-01 至 2027-06-30。生意目标是让上海核心商圈通勤与休闲客流到访南京西路旗舰门店。先看「Campaign 假设书」的七项需求。
2. 点击南京西路旗舰门店，筛出相关媒体。比较公交的沿路重复曝光与地铁的出站指引，并打开一条资源看预算模块、费用和同圈备选。
3. 切 100 → 200 → 500 万。保持行业、档期、媒体、折扣和数据口径相同，后档会保留前档的资源和数量，只增加补频或扩展模块。评委可直接换其他输入，也可在「填写客户需求」中用一句话输入。
4. 在「数据管理」打开「配案检查 → 逐项查看来源」。切换「仅使用已确认资源」，展示严格按资源级覆盖、同档期空位和计价口径出的组合。选一条资源移除，查看新组合与替补。
5. 展示分夜上刊、两晚天气机动、发布验收和补刊口径。导出独立《Campaign 假设书》和客户版 HTML。CSV、Excel 提供内部库存及覆盖字段。

随包的现场版预置食品饮料案例的默认档期数据。截至 2026-11-21，红豆公交文件有 431 条导出记录，另从地铁库核对 20 条出入口。新云大数据覆盖分析以南京西路旗舰门店、静安寺、上海人民广场、上海新天地为中心，统一使用 500 米，平台返回 40 条媒体。公交按线路匹配，地铁覆盖结果仅到站级。红豆给出实际出入口编号和空位。由于缺少实际计价面积及出口级覆盖，地铁候选只进入推荐组合。

复现核验示例时，选择「食品饮料 · 连锁咖啡品牌 A」，保留 2027-06-01 至 2027-06-30，并在「数据管理」选择「仅使用已确认资源」。预算默认留 5% 用于安装、监测等执行费用。实际执行报价由业务团队确认。选其他档期时，需按新起止日期补充同档期红豆导出。

## 如何刷新真实数据

| 来源 | 获取方式 | 导入要点 |
| --- | --- | --- |
| 红豆媒体库 | 在公交或地铁库查询完整目标投放窗，按系统空车数导出 | 导入时选择同一实际查询起止日及导出日期。需要资源名称、空车数、级别。普通地铁口另需实际面积 |
| 新云可视化平台 | 按地标和半径查覆盖，分别导出公交、地铁候选 | 导入时选择相同圈选中心、半径和媒体类型。跨媒体文件可用「媒体」列逐行指定 |
| 可视化平台媒体查询 | 选 2023 年有效月份，获取历史人流 | 可在覆盖模板补入历史月份、指标名和数值，逐个地标查看 |
| 可视化平台 AI 线路 | 对候选线路生成平台授权预览链接 | 可填入覆盖模板的「AI线路链接」，打开后使用平台的线路交互 |

- 支持 XLSX、XLS、CSV。导入对话框可下载两种标准模板。对未识别的字段，把原表数据映射至模板列。已识别的多中心覆盖会按地标拆行，普通地铁口需补具体出口与面积才能进入正式组合。空位数以红豆字段为准。
- 匹配优先用两边一致的资源 ID。缺 ID 时以媒体类型与标准化名称匹配，必要时用形式、运营公司消除歧义。名称有多个候选时保留待核。含混的地铁站名或聚合资源应补具体出入口与唯一资源 ID，避免重复占用。
- 仅完整、相同的查询窗口能进核验模式。资源随导入逐项更新，较新快照覆盖相同窗口同资源，零空位覆盖旧值。快照不锁档。签约前重新查询。
- 导入只保存当前浏览器本地数据。需要把组织方明确允许流转的核验数据预置进现场离线包时，用 `data/verified.local.json`（字段与导入后的结构一致）单独构建。该文件在 Git 中忽略。日常演示可直接导入，无需修改文件。

## 方案与价格

- 五个行业的品牌原型均作匿名处理。公开资料用于了解上海线下经营场景，2027 年活动为演示假设。团队可在 `src/catalog.js` 调整品牌体量、受众、承接动作、地标和权重。
- 目标决定优先场景与媒体配比。组合逐档追加，以新增圈选、资源证据、等级和费用评分，重复覆盖的边际权重递减。资源级证据优先于站级关联。贪心推荐可能留有余量。
- 刊例来自资料 07。区间低位、中值、高位可切换。默认中值，发布费按 100% 刊例测算，折扣可调。制作另计。普通地铁候选的策略演示面积为每处 60 ㎡，实盘按实际面积。已知的独立陆家嘴 6 号口、8 号口及人民广场 16 号口优先使用指定刊例。形式和口径不明的资源不做实盘报价。
- 公交台账是 2026-11-13 单日的静态参考。策略测算中的圈选关联、地铁出口候选、等级和面积需在比赛系统复核。示意图用于路演导航。历史人流保持原指标，原型不汇总为 2027 年曝光承诺。
- 报价按起始日逐月，未满一月进位，以月刊费乘月数及折扣加制作费。执行预留提前从购买上限扣除。中值与高位区间分别保留预算差额。
- 排班按公交 12 辆/夜、地铁 4 处/夜与 2 个天气缓冲夜起算，均可在「数据管理」调整。容量为报价阶段假设，夜间进场由运行团队确认。按合同确认误一补二及补刊交付。
- 效果披露以媒体日、关联场景和去重后的业务 KPI 为主。再用相似未投放圈作对照。没有可用历史人流时，保留媒体量与业务测量方法，待提供原口径后再展示历史值。

## 团队交付

一页说明见 `一页纸说明.pdf`。可编辑 HTML 位于 `docs/one-page.html`。比赛数据的操作入口只指向红豆和新云大数据平台。品牌事实使用公开材料。代码不包含比赛账号、密码、业务会话、合同或占用明细。

「填写客户需求」用离线文本分类识别行业和主目标，再抽取预算、媒体和档期。示例语料与分类词保存在 `src/campaign.js`。识别结果由销售确认后应用，随后由预算与资源约束生成和校验组合，自动更新七项假设。浏览器本地模型处于可用状态时，可参与补充行业或目标。平台 AI 线路图通过业务导出链接使用。

**答辩取舍**　重点圈按人群的行动路径选。以咖啡到店为例，车身让通勤者多次看到旗舰位置，靠近商圈的地铁口承担步行指引。额外预算先增加核心圈媒体密度，再延伸到其他人群场景。用媒体日与实际核销对照追踪，避免把历史客流直接换算成新增订单。
